## 0. 한눈에

- **엔진**: 설계 데이터(JSON)를 그대로 읽어 전투 규칙 전체를 결정적으로 실행하는 TypeScript 엔진. 카드 연산 cond 130 · per 70 · power 34를 **모두 결정적으로** 실행하고, special 14장도 **모두 규칙으로 구현**했다(근사 0).
- **봇**: 한 수 앞보기 탐욕 봇. 보이는 적 의도로 다음 적 턴 피해를 예측하고, 명부·상흔 처형과 해원 진척을 점수로 본다.
- **결과(설계값 그대로)**: 체력이 가득한 단일 전투는 일반·엘리트 거의 100% 이기지만 **체력 손실이 크다**(어려움 13~28, 엘리트 39~48, 보스 81~104). 체력이 이어지는 보통 원정은 **클리어율 중앙 1%(최대 13%)**. 병목은 카드가 아니라 **원정 체력 경제**와 **보스 상여(b2, 단일 전투 승률 2.4%)**다.
- **완화 실험(설계값은 바꾸지 않음)**: 전투마다 15% 회복 + 쓰러진 턴 보호 + 적 피해 −15% → 중앙 39%, 여기에 보스를 뱃사공으로 고정하면 중앙 73% (최소 27% · 최대 94%). 이 조건에서 조합 편차가 드러난다: **잽이·포수·작두박수 조합이 약하고 만신·차사·승려 조합이 강하다.**

## 1. 구조

```
src/core/            헤드리스 엔진 (순수·결정적, Node 표준 라이브러리만)
  types.ts           데이터·상태 타입, RuleVariant(what-if 규칙 변형, 기본 = 설계 그대로)
  data.ts            JSON 로드 → 정적 정의로 컴파일 (op 트리, 조건 파싱, 대상 선택 방식, 해원 조건)
  conditions.ts      cond.if 문장 → 결정적 조건 (60종 문장 전부)
  value.ts           04-cards §2 비용 가치 모델 이식 (card_check.py 와 같은 점수)
  engine.ts          턴 진행·카드 사용·효과 실행·피해·쓰러짐/죽음·굿상·능력·장단·자원·해원
  enemy.ts           적 의도 선택(cycle·weighted·phased·override)·실행·봇용 피해 예측
  fidelity.ts        충실도 집계 (cond·per·power·special 의 결정적/근사 수)
  rng.ts             mulberry32 (상태 = 정수 하나 → 전투 상태와 함께 복제)
src/sim/
  bot.ts             평가 함수 + 행동 열거 + 한 수 앞보기 + 전투 실행
  draft.ts           덱·보상(영웅마다 1장, 희귀도 확률·희귀 보정)·보상 선택 휴리스틱
  expedition.ts      보통 길이 원정 1회
  jobs.ts            조합 단위 작업 (전투 시뮬 / 원정 시뮬)
  pool.ts worker.ts  worker_threads 풀 (코어 4개 병렬)
  combat-sim.ts expedition-sim.ts report.ts   실행 진입점·보고서 생성
tests/               node:test 23개 (규칙·적·재현)
```

- **상태 복제**: 카드 한 장은 불변 객체(`{d, o, o2, orig, x}`)라서 더미 복제가 `slice()` 한 번이다. 영웅·적·굿상·능력만 얕은 복사. lookahead 용 복제에서는 통계 수집을 끈다. 전투 1회 평균 약 3ms(덱 20장).
- **결정성**: 모든 난수는 상태 안의 mulberry32 정수에서 나온다. 같은 시드와 같은 선택이면 같은 전투(테스트로 검증). 시드는 `(조합, 전투, 시드 번호)` 문자열 해시.
- **데이터 흐름**: JSON → `data.ts` 가 op 를 컴파일(조건 문장 파싱, `per` 의 측정 방식 결정, 능력의 트리거 추론, special 의 규칙 연결) → 엔진은 컴파일된 op 만 실행한다. 데이터를 고치면 코드 수정 없이 다시 돌릴 수 있다.

## 2. 실행

```bash
npm install
npm run typecheck                 # tsc --noEmit (strict)
npm test                          # node --import tsx --test 'tests/**/*.test.ts'  (23개)
npm run sim:combat                # 56 조합 × 15 전투 × 40 시드 = 33,600 전투 (약 20초, 워커 4)
npm run sim:expedition            # 56 조합 × 100 원정 (약 25초)
npm run sim:report                # data/sim/*.json → docs/design/sim-report.md (시뮬 끝에도 자동)
```

| 옵션 | 뜻 |
|---|---|
| `sim:combat -- --seeds N --workers K` | 시드 수, 워커 수 |
| `sim:combat -- --duo` | 덱에 그 조합의 합기 3장을 더한 변형 → `data/sim/combat-duo.json` |
| `sim:expedition -- --runs N` | 조합마다 원정 수 |
| `sim:expedition -- --between-heal 0.15` | what-if: 전투가 끝날 때마다 살아 있는 영웅 최대 체력 15% 회복 |
| `sim:expedition -- --down-shield` | what-if: 막 쓰러진 영웅은 그 적 턴에 더 맞지 않고 가장 앞의 서 있는 영웅이 맞는다 |
| `sim:expedition -- --enemy-dmg 0.85` | what-if: 적 피해 배수 |
| `sim:expedition -- --boss b1` | what-if: 보스 고정 |
| `sim:expedition -- ... --out 이름` | 결과 파일 이름 (what-if 는 기본 `expedition-whatif`) |

> `package.json` 의 `test` 는 `tests/` 디렉터리 대신 글롭(`'tests/**/*.test.ts'`)을 쓴다. Node 22 의 `--test tests/` 는 디렉터리를 모듈로 불러오려다 실패한다.

## 3. 규칙 해석·근사 (구현에서 고른 읽기)

문서에 수치가 없거나 문장이 두 가지로 읽히는 곳이다. 모두 엔진의 한 곳에서 바꿀 수 있다.

| 항목 | 고른 읽기 |
|---|---|
| 버팀 | `clamp(round(최대 체력 × 0.35), 6, 40)` (데이터에 없음). 붕괴: 다음 의도 취소, 받는 피해 ×1.5 가 **다음 플레이어 턴 끝까지**, 넋흔들림 0, 버팀 ×1.5(반올림) |
| 피해 계산 | 기본 → 공격자 약화 ×0.75 → (회복 중 ×0.9) → 취약 ×1.5 → 붕괴 ×1.5 → 내림 → 방어도. 타격마다 따로 계산 |
| 장단·받는소리 | 턴 첫 카드는 성립하지 않음. 합기·'파티' 카드는 항상 다른 주인. 합기 다음 카드는 그 두 주인이면 불성립. 장단 +1 은 효과보다 먼저 |
| 돌격 | 공격 카드(타입 '공격')만. 위치 조건은 낼 때의 칸으로 판정, 이동은 효과 뒤. 합기는 문장에서 마지막 '피해' 앞에 이름이 나온 영웅. 홀린 카드도 돌격은 한다(“성질 그대로”). 승려 「버티고 서기」는 그 턴 선두 고정 |
| 부적(토큰) | 만든 카드의 주인을 물려받는다. 타입이 없는 부적은 '기술'(돌격·공격 트리거 없음). 손이 가득하면 버린 더미로. 「호신부」의 수호부는 문장대로 **다음 턴 시작**에 만든다 |
| 굿상 | 최대 3, 넘치면 가장 오래된 것이 내려간다. 지속 = 발동 횟수. 적의 '굿상' 공격은 설치물 하나를 무너뜨린다(설치물에 체력 데이터가 없음). 신령부는 담아 온 설치물의 효과를 한 번 실행 |
| 만신 신바람·강신 | 만신 카드(단독 주인)를 직전 카드도 만신일 때 +1. 5가 되면 즉시 **강신**(이번 턴, 신바람 0) → 공수 카드 사용 가능, 턴 종료에 가장 강한 신령 하나(무복 갈아입기로 +1)가 한 번 더 발동 |
| 잽이 가락 | 0~2 단계(굿거리·자진굿거리·당악). 잽이 카드를 낸 **뒤** +1, 턴 종료 −1(삼현육각이면 고정). 당악이면 그 턴 모든 받는소리 효과 2회. 바라지 = 다음 다른 영웅 카드의 받는소리 +1회 |
| 작두 | '작두에 오른다' = 자세 켜기. 작두 위 공격 보너스(능력)는 자세일 때만. **턴 종료에 장단 < 2 이면 헛디딤(체력 6)** — 카드 사용 시점의 cond 가 아니라 턴 종료 규칙으로 처리 |
| 경면주사·염주·화약·오라 | 경면주사 매 턴 +1(최대 3, 진사 그릇 5) — 부적 자동 강화는 하지 않음(카드 문장에 있을 때만). 염주는 방어도를 얻을 때·피격 때마다 +1. "X 1을 쓰면" 은 자원이 있으면 **항상 쓴다** |
| 오라·묶기 | 오라 1을 써서 대상 묶기. 묶인 적의 **다음 행동 피해 ×0.75**(약화와 같은 폭, 가치 모델의 오라 2.5점에 맞춤). 이름 석 자: 묶인 적은 명부 ≥ 체력/2 에서 처형 |
| 엄호 | 이번 턴(적 턴 포함) 지정 아군이 받을 공격을 대신 받는다. 아직 때가 아니다: 쓰러진 아군이 받을 공격을 차사가 받는다 |
| 홀림 | 그 영웅의 카드(단독 주인)는 효과 없음, 비용·장단·돌격은 그대로, 낼 때마다 −1. 정화는 홀림 → 손의 저주·상태 → 버린 더미 → 뽑을 더미 순. 아전 「장부 대조」 방어도 3 |
| 적 대상 | '무작위'·'최저/최고 체력'은 **서 있는** 영웅 중에서. 선두·중열·후열·전체는 쓰러진 영웅도 맞는다(사망 판정). 영웅이 둘이면 후열 = 마지막 칸. 뱃사공 2단계는 단일 대상 공격을 쓰러진 영웅에게 돌린다 |
| 적 효과 문장 | 공격 +N(누적)은 피해가 있는 모든 의도에. 끌어당김은 피해 뒤 이동. 의도 'weighted' 의 `no_repeat: 2` = 같은 의도 연속 금지. 상여 override = 상여꾼(minion) ≤ 2 이면 매 턴 c. 넋 쏟기 소환 상한은 '소환된 넋' 기준 |
| 쓰러짐·죽음 | 쓰러지면 그 영웅 단독 카드(부적 포함, 저주·상태 제외)가 넋 부르기로. 넋 부르기는 다른 카드처럼 받는소리·장단을 만든다. 방어도로 다 막은 피격은 사망 판정 없음. 전멸 시 영웅마다 50% 판정은 원정 통계에만 반영 |
| 귀기 | 0~100. 50·100을 넘을 때 그 영웅의 씌임 4종 중 무작위 1장(전투 상태 카드 상한 4 공유). 100: 75% 붕괴 = 홀림 2 / 25% 각성 = 파티 방어도 6 + 장단 2. 귀기원은 적 의도·저주뿐(동료 쓰러짐 귀기는 Phase 6 수치가 없어 넣지 않음). 해원 1회 = 파티 귀기 −5 (수치 없음, 가정) |
| `per` | 상태(점지·상흔·명부·넋흔들림)는 **대상의 실제 스택**. 효과가 적 전체이면 **적마다 자기 스택**(울림·저승 판결·천도재). 같은 카드에서 먼저 소모한 양이 있으면 그 양(넋 거두어·왕생 발원·부적 사르기). 부적은 "손에 든"이면 손의 부적 수, 아니면 이번 턴 쓴 부적 수. "이번 턴 진형이 바뀔 때마다" 는 **이번 턴 임시 트리거**, "바뀐 횟수" 는 실제 횟수. 「수부장단」 "이번 턴 종료 시 남은 장단" 은 턴 종료에 처리 |
| `cond` 대상 조건 | 고른 대상이 없는 카드(적 전체)의 "…인 적에게는" 은 **조건을 만족하는 적마다** 적용(휘모리·고리 소리·산탄 세례·탈판 한마당·번지는 칼금) |
| `cond` 특수 | 강신 공수 = 사용 조건(강신이 아니면 낼 수 없음). 숨통 겨누기: 화약을 쓰면 점지 소모를 건너뜀. 이번 턴 장단이 5가 되면(오장): 지금 5가 아니면 이번 턴 임시 트리거. 길 막아서기: 이번 턴 차사를 친 적에게 점지·명부(임시 피격 트리거) |
| `power` | 트리거가 없는 7개는 문장("턴 시작/종료")과 첫 `consume source` 힌트(부적 → 부적을 쓸 때, 진형 → 진형이 바뀔 때, 신바람 → 강신할 때)로 정했다. "매 턴 처음" 은 턴당 1회. 주인이 쓰러지면 정지. 알 수 없는 트리거는 턴 종료에 min(1, expect/3.5) 확률(현재 0개) |
| "다른 적 하나" | 자국 옮겨 새기기·동명이인: 수는 고른 대상에서 세고 효과는 두 번째 적(체력이 가장 높은 다른 적)에게 |
| 보상·덱 | 원정 중반 덱 = 시작 12장 + 일반 보상 8번(반드시 고름). 보상은 살아 있는 영웅마다 1장(희귀도 확률·희귀 보정 −5%, 희귀가 아니면 +1%). 합기는 기본 보상에서 빠짐(인연 해금 전제) — `--duo` 변형으로 따로 잰다 |
| 원정 | 쉬움 2(서로 다른 조합) → 어려움 7(6종 다 쓴 뒤 반복, 연속 금지) 사이에 수호 방 1~2(서로 다름) → 6번째 전투 뒤 길굿 → 보스 b1/b2 무작위. 지전 3을 들고 간다. 길굿 = **쌀 4로 끼니(체력 30%·귀기 −10·중상 치료) 또는 시작 카드 1장 제거**(어떤 영웅이 60% 미만이거나 중상이면 끼니). 기물·이벤트·덫·가호·오방기·넋등(그늘)은 넣지 않았다 |

## 4. 충실도

`src/core/fidelity.ts` 가 카드·부적·설치물 326개의 op 트리 전체를 센다.

| 연산 | 전체 | 결정적 실행 | 근사(스텁) |
|---|---:|---:|---:|
| cond | 130 | **130** | 0 (확률 판정 0) |
| per | 70 | **70** | 0 (expect 대입 0) |
| power | 34 | **34** | 0 (알 수 없는 트리거 0) |

## 7. 발견

1. **원정 체력 경제가 설계의 병목이다.** 단일 전투 체력 손실을 원정 구성에 더하면 쉬움 2×10 + 어려움 7×~20 + 수호 방 1.5×~43 + 보스 81~104 ≈ **310** 인데, 파티 체력은 약 105 + 길굿 30% 한 번(≈ 31)뿐이다. 그래서 기준 원정 중앙 클리어 1%, 평균 7.9 전투에서 전멸한다. 카드·조합을 바꿔도 이 차이는 메워지지 않는다(최대 13%).
2. **상여(b2)가 벽이다.** 체력이 가득해도 2.4%, 완화 실험 W3에서도 7%. 상여꾼 4명이 2턴마다 4씩 치고, 넋 쏟기로 다시 불러내는 넋(3×2)이 붙고, 해원 조건이 상여꾼을 살려 두라고 요구하는 동안 상여 150을 깎아야 한다 — 매 턴 15~20 피해를 12턴 넘게 받는다. 메모리 안 실험(56 조합 × 5 시드, 기준 4.3%): 상여 체력 110 → 17.5%, + 넋 쏟기 최대 1 → 46%, + 상여꾼 피해 3 → **67.5%**(뱃사공 81%과 비슷).
3. **쓰러지는 순간 죽는다.** 사망의 **50~54%가 쓰러진 그 적 턴**에 일어난다(선두에서 쓰러진 뒤 남은 '선두' 공격이 이어서 사망 판정: 3타면 생존 16%). 핵심 규칙 §6의 "플레이어에게 항상 구할 기회가 있다" 와 어긋난다. 쓰러진 턴 보호 변형으로 단일 전투 사망 0.16 → 0.09/전투, 원정 사망 2.05 → 1.78/원정.
4. **근접 화력·중간형이 수호형만큼 맞는다(O2).** 받은 피해 비율: 작두박수 42%(체력 32) = 승려 42%(체력 45), 탈꾼 36%, 차사 39% vs 원거리 26~28%. 피격의 70%가 선두. 돌격 규칙 때문에 "마지막에 누가 공격했나" 가 곧 "누가 맞나" 이고, 화력 근접이 가장 자주 마지막에 공격한다.

12. **조합 차이는 작게 시작한다.** 체력 가득 단일 전투 승률은 88.5~93.7%로 거의 같고, 차이는 보스 b1(33~100%)과 원정에서 벌어진다. 연계 강도 최소 쌍(만신+포수)이 든 조합도 하위가 아니다 — 하위는 **수호형이 없고 체력이 낮은 조합**(잽이·포수·작두박수)이다(영웅 §5 "수호형 없는 조합 36%" 점검 대상과 일치).

## 2. 비용 가치 모델

모든 카드의 효과를 점수로 환산해 **예산의 80~120%** 안에 들게 한다(기본 카드는 70~115%).

### 예산

| 비용 | 0 | 1 | 2 | 3 | X |
|---|---:|---:|---:|---:|---|
| 기본 예산 | 4 | 8 | 16 | 25 | 에너지 1당 효과를 쓰고 ×3으로 평가, 예산 24 |

- **희귀도 배수**: 기본 0.85 · 일반 1.0 · 고급 1.12 · 희귀 1.25 · 합기 1.3 · 공용 1.0
- **키워드 배수**(예산에 곱한다): 소멸 1.3 · 휘발 1.15 · 선천 0.92 · 보존 0.95
- 근거: StS 기본 카드 1코스트 = 피해 6 / 방어도 5. 비용이 오를수록 에너지당 효율이 오른다(메커닉 지도 §3).

### 효과 점수

| 연산(op) | 점수 |
|---|---|
| `dmg` 피해 n × 타수 | 대상 하나 1.0 · 적 전체 1.6 · 무작위 0.9 (n당) |
| `block` 방어도 n | 주인 1.2 · 아군 하나 1.3 · 파티 전체 2.4 (n당) |
| `draw` 드로우 | 4 / 장 |
| `discard` 버리기 | −1 / 장 |
| `energy` 에너지 | 이번 턴 8 · 다음 턴 6 / 1 |
| `apply` 상태 부여(대상 하나) | 취약 3.5 · 약화 3.0 · 점지 2.0 · 상흔 1.7 · 명부 1.3 · 넋흔들림 1.1 (스택당). 적 전체 ×1.6 |
| `jangdan` 장단 +n | 2 / 1 (주인 교대로 오르는 기본 장단과 별개) |
| `personal` 개인 자원 +n | 2.5 / 1 |
| `move` 진형 | 전진·후퇴 2 · 교대 3 · 엄호 6 |
| `summon` 굿상 설치물 | (한 번 발동 점수) × 지속 턴(없으면 3) × 0.75 |
| `token` 부적 카드 생성 | (부적 1장 점수) × 장수 × 0.85 |
| `heal` 회복 n | 1.5 / 1 (아군 하나 ×1.1, 파티 ×2.4) |
| `stress` 귀기 −n | 0.4 / 1 (파티 대상) |
| `cleanse` 씌임·홀림·상처 정화 | 3 / 장 |
| `exhaust_other` 다른 카드 소멸 | 2 / 장 |
| `hp_loss` 체력 손실 | −1 / 1 |
| `per` "X 1당 효과" | (효과 점수) × 기대 스택 × 0.9. 기대 스택 기본값(v0.3): 점지 4 · 상흔 2 · 명부 5 · 넋흔들림 5 · 장단 2 · 굿상 1 · 부적 0.5 · 개인 자원 2 · 그늘 1 · 손패 4 (§2.1) |
| `cond` 조건부 | (then 점수) × 성립 확률 + (else 점수) × (1 − 성립 확률). 기본 성립 확률은 §2.1 표(카드에 `p`로 지정 가능) |
| `power` 능력(지속) | (한 번 발동 점수) × 기대 발동 횟수 × 0.75. 기대 발동 횟수 기본: 턴 시작·턴 종료 5, 그 밖 3.5(카드에 `expect`). **이번 턴만**(`this_turn`) 능력은 × 기대 발동 × 0.9, 기본 0.15 |
| `consume` 상태·자원 소모 | 0 (보상 쪽 `per`·`cond`에 반영) |
| `special` 계산이 어려운 효과 | 카드에 직접 `value`와 근거 `note`를 적는다. 영웅마다 3장 이하 |

> 이 모델은 *출발점*이다. 정확한 균형은 Phase 7 시뮬레이션에서 카드 사용률·승률로 다시 맞춘다. 지금의 목적은 **270장이 같은 잣대 위에 서는 것**이다.

### 2.1 가치 모델 교정 (S10, v0.3 — K2·K3)

조건 성립 확률(p)·`per` 기대 스택·능력 기대 발동 횟수를 **원정 시뮬레이션의 실측**으로 바꿨다. 실측 원자료: v0.2.1 데이터로 돌린 `sim:expedition --runs 200`(56 조합, 원정 11,200회, 전투 약 12.8만)과 합기 변형 `sim:combat --duo`. 엔진에 `per` 측정(실행마다 센 수)을 새로 넣었다(`CombatStats.perCount` → `data/sim/*.json` 의 `pers`).

**규칙**: 실측이 충분하면(조건 평가·`per` 실행 300회 이상, 능력 사용 200회 이상) 실측을 쓴다. 모델 기본값과 가까우면(p 0.1 미만 차, 기대값 10% 이내) 카드에서 `p`·`expect` 를 지우고 기본값을 쓰고, 아니면 카드에 실측값(p 0.05 단위, 기대값 3 미만 0.1 단위·그 위 0.5 단위)을 적는다. 시뮬레이터가 만들지 않는 상황(손의 **그늘**, 「이번 턴 차사를 공격하는 적」)은 바꾸지 않았다. 두 검사기(`card_check.py`·`src/core/value.ts`)는 같은 기본값을 쓴다.

| 항목 | v0.1~v0.2 | **v0.3** | 실측(근거) |
|---|---:|---:|---|
| 받는소리 | 0.6 | **0.65** | 0.68 (42장, 0.30~0.87 → 차이가 큰 13장은 카드에 p) |
| "경면주사·염주 N을 쓰면" | 0.5 | **0.95** | 1.00 · 0.93 (매 턴 자동으로 쌓인다, K3) |
| "이번 턴 진형이 바뀌었으면" | 0.5 | **0.15** | 0.11~0.14 |
| "손의 부적을 … 바치면" | 0.5 | **0.1** | 0.02~0.11 |
| "강신 중이면" | 0.3(카드) | **0.35** | 0.29~0.39 |
| 붕괴가 들어간 조건 | 0.4~0.5(카드) | **0.15** | 0.13~0.18 (포수 6장). 승려처럼 스스로 넋흔들림을 넣는 카드는 카드에 p(0.5~0.55) |
| 그 밖의 조건 | 0.5 | 0.5 | 카드마다 실측(작두 위 0.2~0.6, 점지된 적 0.35~0.7, 후열 0.25~0.3, 가락 당악 0.2~0.25 …) |
| 능력 기대 발동 — 턴 시작·종료 | 3.5 | **5** | 중앙 약 5 (4.2~6.4) |
| 능력 기대 발동 — 그 밖 | 3.5 | 3.5 | 카드마다 실측: 작두 오르기 1.0, 맨발의 영험 1.2, 묶인 이름 0.9, 거둔 표적 0.6, 덧나는 탄환 2.3, 양반 행세 8, 탈놀음판 6 |
| 이번 턴 트리거(진형이 바뀔 때마다) | per(진형) 2 | **0.15** | 0.16 (장단 바꿈·춤사위·발디딤) |
| 기대 스택 점지 / 상흔 / 명부 / 넋흔들림 | 2.5 / 4 / 6 / 6 | **4 / 2 / 5 / 5** | 3.1~4.7 / 0.4~3.6 / 2.7~9.9 / 5.3 |
| 기대 스택 장단 | 3 | **2** | 카드를 낼 때 0.9~2.0, 턴 종료에 3~3.7(그 카드들은 카드에 expect) |
| 기대 스택 굿상 / 부적 | 1.5 / 2 | **1 / 0.5** | 0.5~1.4 / 0.03~0.9 |
| 기대 스택 개인 자원 | 2 | 2 | 경면주사 2.4~2.6, 화약 0.9, 염주 4.4(카드마다) |

- 바뀐 곳: 조건 p 75 · per 기대 스택 50 · 능력 기대 발동 19 (카드 81장은 p·expect 만 바뀌었다).
- **읽는 법**: 실측은 *한 수 앞만 보는 봇* 기준이다. 카드 순서를 계획해야 커지는 값(이번 턴 쓴 부적 수, 카드를 낼 때의 장단, "진형이 바뀌었으면")은 봇이 낮게 만든다. 그 카드들은 교정 뒤 예산을 맞추려고 수치가 올라갔으므로, 순서를 잘 짜는 사람에게는 조금 강할 수 있다(§7 K6).

## 3. 카드 문장 규칙

| 규칙 | 내용 |
|---|---|
| 용어 | 핵심 규칙 §10 이름표를 쓴다: 장단, 받는소리, 점지, 상흔, 명부, 넋흔들림, 붕괴, 굿상, 부적, 선두·중열·후열, 전진·후퇴·교대·엄호, 홀림, 씌임, 그늘, 소멸, 휘발, 보존, 선천, 방어도, 취약, 약화 |
| 받는소리 | "받는소리: [효과]" = 직전에 쓴 카드의 주인이 다르면 추가 효과 |
| 이름 | **모두 새로 짓는다.** 레퍼런스 게임 카드 이름을 번역해 쓰지 않는다. 굿·무구·장단·민속에서 온 우리말 이름을 우선한다 |
| 효과 조합 | 레퍼런스 카드 한 장의 효과 조합과 수치를 그대로 옮기지 않는다(메커닉 원자로 다시 조합) |
| 재현 윤리 | 금지어: 광기·미친·발작·정신병·악마·마녀·지옥불·선혈·내장·피범벅. 씌임은 "귀신이 붙었다"는 표현으로만. 실존 신령·인물 이름 금지(신령은 가상 이름이나 일반 범주명) |
| 강화 | 카드마다 `upgrade` 객체(§3.1). 수치 +15~45% 또는 비용 −1 또는 키워드(선천·보존 얻기, 휘발·소멸 없애기). 강화판 문장은 **강화된 카드의 전체 문장** |

### 3.1 강화판 (K1, v0.3)

```jsonc
"upgrade": {
  "text": "적 하나에 점지 3. 화약 +1. (화약: 최대 3, 턴을 넘겨 남는다)", // 필수: 강화된 카드의 전체 문장
  "cost": 0,                // 선택: 없으면 기본판 비용 (같거나 1 낮게)
  "keywords": ["선천"],      // 선택: 없으면 기본판 키워드 (바꾸면 목록 전체)
  "effects": [ ... ]        // 선택: 없으면 기본판 효과 (바꾸면 효과 전체)
}
```

- 저주·상태와 공물 행동(「노잣돈 바치기」)은 강화하지 않는다(`upgrade` 없음). 그 밖의 **280장**이 강화판을 갖는다: 수치 244 · 비용 −1 22 · 키워드 14.
- **강화판 가치 검사**: 강화 가치 = (강화판 가치 + 비용 −1 이면 예산표의 에너지 1 값) / (기본판 비용의 예산(강화판 키워드) × **1.3**). 희귀도의 대역(기본 0.70~1.15, 그 밖 0.80~1.20) 안에 들어야 한다. 비용 −1 의 값은 같은 희귀도에서 두 비용의 예산 차(1→0: 4 · 2→1: 8 · 3→2: 9, × 희귀도 배수)로 친다 — 예산표가 에너지에 매긴 값 그대로다.
- **진짜 강화인가**: ① 수치 강화는 가치 +15~45% ② 비용 −1 은 효과가 줄지 않을 것 ③ 키워드는 선천·보존 얻기, 휘발·소멸 없애기만(효과가 줄지 않을 것). '받는소리' 키워드는 효과 안내라 변경으로 치지 않는다.
- 강화판이 수입 자원을 생산하면 오류(C5). 강화판이 쓰는 부적·설치물도 같은 파일에 있어야 한다(예: 「제석 맞이+」의 `jaebi.s_jeseok_up` 4턴, 「앉은굿 장단+」의 `duo.s_gyeongsinjang_up`).
- 강화 가치 범위(영웅별): [카드 전체 요약](design/cards-overview.md). 카드마다 강화판 문장·비용·키워드 변경과 강화 가치(수치 강화는 증가율)를 `docs/design/cards-<영웅>.md` 에 싣는다.
- 옛 강화 문장(짧은 차이 문장)에서 숫자를 맞춰 강화판 효과를 만들고, 기본판 수치가 S10 으로 바뀐 카드는 강화판 수치도 +15~45% 안으로 다시 맞췄다. 정수 한 칸이 +50%를 넘는 작은 카드(점지 2, 장단 +1 등)는 비용 −1 또는 보존·선천으로 바꿨다.

## 4. 데이터 형식

```jsonc
// data/cards/<영웅 id>.json
{
  "hero": "posu",
  "version": "0.1",
  "tokens":  [{"id": "posu.t_...", "name": "...", "cost": 0, "keywords": ["소멸"], "text": "...", "effects": [ ... ]}],
  "summons": [{"id": "manshin.s_...", "name": "...", "trigger": "turn_end", "duration": 3, "text": "...", "effects": [ ... ]}],
  "cards": [{
    "id": "posu.jojun", "name": "조준", "type": "기술", "rarity": "기본", "cost": 1,
    "starter": true, "path": "core",
    "keywords": [],
    "text": "적 하나에 점지 2. 화약 +1.",
    "effects": [{"op": "apply", "status": "점지", "n": 2, "target": "one"}, {"op": "personal", "n": 1}],
    "tags": {"produce": ["점지"], "consume": []},
    "upgrade": "점지 3. 화약 +1."
  }]
}
```

- **v0.3 연산 추가**: `cond` 의 `else`(조건이 아니면 — 「숨통 겨누기」), `cond` 의 `when: "turn_end"`(턴 종료에 판정 — 작두 헛디딤), `token` 의 `when: "next_turn"`(다음 턴 시작에 — 「호신부」), `power` 의 `this_turn: true`(이번 턴만 — "이번 턴 진형이 바뀔 때마다"). 능력의 `trigger` 는 엔진 이름만 쓴다: `turn_start` · `turn_end` · `on_attack` · `on_hit` · `on_bind` · `on_formation_change` · `on_formation_change_first` · `on_talggun_move` · `on_talggun_move_first` · `on_token_play` · `on_gangsin` · `on_consume_mark` · `on_owner_card` · `on_summon_fire`. 부적은 `type`(기술·공격)을 꼭 적는다.
- `tags.produce` / `tags.consume`에는 공용 상태·매개체(점지·상흔·명부·넋흔들림·장단·진형·굿상·부적·취약·약화)와 그 영웅의 개인 자원 이름을 쓴다. 검사기가 효과에서 추론한 것과 다르면 경고한다.
- 합기 카드(`duo.json`)는 `"owners": ["a", "b"]`, 희귀도 `합기`.
- 공용(`common.json`)은 주인 `"파티"`, 저주·상태는 `type` 저주/상태, 가치 검사 제외.

## 5. 검사 항목 (`tools/design/card_check.py`)

- 형식: id 유일(영웅 id 접두어), 이름 유일(전 파일), 키워드 허용 목록, 부적·설치물 참조 존재
- 수량: 시작 4, 보상 풀 26(일반 11·고급 10·희귀 5 ±1), 타입 범위, 방어 수단, 비용 분포, 길 A·B 각 7장 이상
- 자원: §1 표의 기준(시그니처·수출·수입·범용·개인 자원), 수입 자원 생산 0장
- 가치: 모든 카드가 예산 80~120%(기본 70~115%)
- 윤리: 금지어 없음
- 출력: `docs/design/cards-<영웅>.md`(카드 목록), `docs/design/cards-overview.md`(전체 요약)

### 검사기 v2 (최종 검수에서 강화)

- 자원 집계는 **효과에서 추론한 것 + 선언 태그**. 효과에서 추론되지 않는 선언 태그는 영웅당 3개까지만 인정한다(수량 부풀리기 방지).
- 추론은 부적·설치물의 효과 안쪽까지 들어가고, 조건 문장의 '붕괴'는 넋흔들림, '선두·중열·후열'은 진형으로 읽는다.
- 방어 수단·special 집계도 부적·설치물 안쪽을 센다(special은 카드·부적·설치물 합쳐 영웅당 4개 이하).
- 합기 카드에 '받는소리' 키워드 금지(항상 성립하므로).
- 합기·공용 파일의 부적·설치물 문장도 금지어 검사. 부적·설치물 이름 중복은 경고.
- **로스터 연계**: 카드 데이터에서 다시 계산한 영웅 쌍 28개의 연계 강도(Σ 자원 min(A 생산 장수, B 소비 장수) + 반대 방향)가 모두 2 이상.

### 검사기 v3 (v0.3 반복 1)

- **강화판**: 형식(`{text, cost?, keywords?, effects?}`), 가치 대역·진짜 강화(§3.1), 비용(같거나 1 낮음), 키워드 변경 허용 목록, 금지어, 수입 자원 생산 0(C5). 저주·상태·공물 행동에 강화가 있으면 오류.
- **능력 trigger** 는 허용 목록(§4), **부적 type** 필수, **설치물 trigger** 는 turn_start·turn_end.
- 가치 모델 기본값(§2.1)은 `card_check.py` 와 `src/core/value.ts` 가 같다. 문서 표에 강화판 문장·강화 가치를 함께 싣는다.

## 7. 열린 문제

| # | 문제 | 검증 |
|---|---|---|
| K1 | 강화판은 문장만 있고 가치 검사를 하지 않았다(+20~45%로 손으로 맞춤) | Phase 7 전에 강화판도 효과 구조로 옮겨 검사 |
| K2 | 능력 카드의 기대 발동 횟수, 조건 성립 확률(0.4~0.7)은 추정값 | Phase 7 시뮬레이션의 실제 발동 횟수로 교정 |
| K3 | 자동으로 쌓이는 개인 자원(염주·경면주사)의 기대치가 과소평가됐을 수 있다 | 같음 |
| K4 | 기준 최솟값에 딱 걸린 수치가 많다(예: 만신 점지 3장, 잽이 부적 3장) → 카드 하나만 고쳐도 검사가 깨진다 | 수정할 때마다 `card_check.py` 실행 |
| K5 | 저승 판결(명부 두 배) 같은 희귀 카드의 폭발력 | 시뮬레이션의 승률·턴 수 분포 |
